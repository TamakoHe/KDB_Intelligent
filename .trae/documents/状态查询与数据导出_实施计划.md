# 实施计划：状态查询与数据导出（Gen2 & Gen3）

## Summary

在现有 TypeScript SDK（已支持 token 鉴权与基础 HTTP 请求）的基础上，新增两类能力并同时覆盖 Gen2 与 Gen3：

- **状态查询**：支持电池管理表状态查询 + “最新上报/复合接口”的状态视角。
- **数据导出**：支持 Excel 文件流下载并落盘，覆盖电池管理列表导出与指定的日志类导出（通信/命令/上报）。

交付形态：

- 通过 SDK 方法调用（复用 `createKdbClients()` + `KdbSiteClient`），不在测试代码里手写 `fetch`。
- 提供可执行的 `tsx` 集成测试脚本验证“查询/导出”最小闭环。

## Proposed Changes

### A. Core 层：补齐“Ruoyi 风格 query”与“二进制下载”

#### A1. 新增 `src/core/http/query-string.ts`

目标：支持把嵌套对象 query（仅一层即可满足 `params[xxx]`）序列化为 querystring。

- 输入类型（计划）：
  - `QueryValue = string | number | boolean | null | undefined`
  - `QueryObject = Record<string, QueryValue | Record<string, QueryValue>>`
- 输出：
  - `URLSearchParams` 或 `string`
- 序列化规则：
  - `query = { batteryId: "8F..." }` -> `batteryId=8F...`
  - `query = { params: { likeBatteryId: "8F,9A" } }` -> `params[likeBatteryId]=8F,9A`
  - `null/undefined` 跳过

#### A2. 扩展 `src/core/http/http-client.ts`

目标：

- **JSON 请求**继续保持现状（不破坏已有调用）
- 增加 **文件下载**能力（ArrayBuffer）
- query 使用 A1 的序列化逻辑（以支持 paramsMap）

拟新增/调整点：

- 调整 `RequestOptions.query` 的类型为 `QueryObject`（向后兼容：原先扁平对象仍然可用）
- 新增方法：
  - `requestArrayBuffer(request: RequestOptions): Promise<HttpResponse<ArrayBuffer>>`
- 兼容导出接口：
  - `POST /xxx/export` 通常不需要 JSON body，SDK 侧以 **POST + querystring** 调用（body 省略）

#### A3. 新增 `src/core/export/download.ts`

目标：将 `ArrayBuffer` 落盘，统一处理：

- 解析 `Content-Disposition` 中的文件名（若存在）
- 确保输出目录存在
- 写入 `.xlsx`（或由响应头决定）

对外函数（计划）：

- `getDefaultOutputDir(cfg: RuntimeConfig): string`（使用 `cfg.app.default_output_dor`）
- `resolveOutputPath(args: { outputPath?: string; defaultDir: string; defaultName: string }): string`
- `saveArrayBuffer(args: { data: ArrayBuffer; outputPath: string }): Promise<void>`

## Assumptions & Decisions

- 继续以 token 模式为主（不依赖验证码登录）。
- 导出请求使用 **POST + querystring**（不发送 JSON body），以适配后端 `export(HttpServletResponse, Entity)` 的参数绑定方式。
- query 嵌套对象只实现一层展开（覆盖 `params[xxx]` 和未来常见扩展）。
- 文件名优先从 `Content-Disposition` 推断；若没有则使用 SDK 默认命名规则。
